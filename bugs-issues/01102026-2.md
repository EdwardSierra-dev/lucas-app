Issue Title
[Bug / Feature] Implement User Profile Menu (Logout, Edit Name) & Personalize Dashboard Greeting

Description / Context
A critical UI/UX flaw was identified in the authentication flow: once logged in, users have no visual option within the platform to log out. Additionally, to enhance UX and personalization, we need to implement a User Profile Dropdown Menu and update the Dashboard greeting to display the user's name instead of their email address.

Requirements / User Stories
1. User Profile Menu (Header / Navbar)
User Dropdown / Avatar: Add a user menu in the top navigation bar that reveals the following options when clicked:

Edit Profile / Name: Option to update or add the user's name (in case it wasn't provided during registration).

Log Out: Action to invalidate the current session/token and redirect the user back to the Login screen.

2. Profile Edit Flow
Provide a modal or view allowing the user to update their Name field.

Ensure the updated name persists in the database and updates the global user state dynamically without requiring a full page refresh.

3. Dashboard Personalization
Welcome Message: Update the greeting in the top-left corner of the Dashboard (e.g., "Hola, [Name]").

Fallback: If the user has not set a name yet, use a friendly default fallback or display a prompt to set it, rather than rendering their raw email address.

Acceptance Criteria
[ ] Functional Logout: The user can log out from the User Menu and is correctly redirected to the Login page.

[ ] Protected Routes: After logging out, pressing the browser's "Back" button must not grant access to the Dashboard without re-authenticating.

[ ] Name Editing: The user can successfully enter, edit, and save their display name.

[ ] Personalized Greeting: The Dashboard greets the user using their Name instead of their Email.

[ ] State Syncing: Changing the name in the Profile immediately updates the Dashboard greeting across the app.

State Management: Ensure user data (name, email) and session status are managed in a global state context (e.g., AuthContext, Zustand, Redux) so both the Header and Dashboard share a single source of truth.
